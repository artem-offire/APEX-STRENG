# План впровадження: Рекомендації відновлення мʼязових груп та Push-сповіщення

У відповідь на ваш вибір реалізуємо систему розрахунку готовності м'язових груп на основі фізіологічного інтервалу відновлення (48–72 години), інформаційну картку на головному екрані «Тренування» та механізм Push-сповіщень, коли м'язи досягають 100% відновлення.

---

## 1. Архітектура та математика відновлення

### Фізіологічні інтервали (48–72 години)
Згідно з даними спортивної фізіології та відповіддю користувача:
- **Великі м'язові групи (72 години / 3 доби):**
  - Спина (`BACK`), Квадрицепси (`QUADS`), Задня поверхня стегна (`HAMSTRINGS`), Сідниці (`GLUTES`).
- **Середні м'язові групи (60–72 години):**
  - Грудні (`CHEST`) — 60 годин, Дельти (`SHOULDERS`) — 48–60 годин.
- **Малі м'язові групи (48 годин / 2 доби):**
  - Біцепс (`BICEPS`), Тріцепс (`TRICEPS`), Прес (`ABS`), Литки (`CALVES`), Передпліччя (`FOREARMS`).

### Розрахунок статусу:
Для кожної групи м'язів аналізується історія останніх виконаних підходів/сесій (`allCompletedSets` / `completedSessions`):
- `lastTrainedTimestamp`: час завершення останнього робочого підходу на цю групу.
- `elapsedHours = (currentTime - lastTrainedTimestamp) / 3600_000`.
- `recoveryProgress = (elapsedHours / targetRecoveryHours).coerceIn(0.0f, 1.0f)`.
- `nextRecommendedTimestamp = lastTrainedTimestamp + (targetRecoveryHours * 3600_000)`.
- **Стани готовності:**
  - `READY` (100%): "Повністю відновлено" — готово до тренування (м'ятний індикатор `IceCyanPrimary`).
  - `OPTIMAL_RECOVERY` (75–99%): "Майже відновлено" — відновлення завершується (блакитний індикатор).
  - `RECOVERING` (<75%): "Відновлюється" — показує точний час до готовності (наприклад, "Через 14 год" або "Завтра о 16:30").
  - `NEVER_TRAINED` / `RESTED`: "Готово (не тренувалось нещодавно)".

## 2. Інформаційна картка на головному екрані «Тренування» (`TrainingTab.kt`)

Розміщення у стрічці екрана «Тренування» (між карткою швидкого запуску та блоком розминки/заминки):
1. **Заголовок картки:** «ГОТОВНІСТЬ МʼЯЗІВ ДО НАВАНТАЖЕННЯ» з іконкою відновлення та пульсу.
2. **Головна рекомендація:** «Сьогодні рекомендовано тренувати: Спина, Біцепс (відпочинок 74 год)» або «Усі групи відновлені».
3. **Візуальні індикатори м'язів:**
   - Горизонтальний ряд або сітка з компактними чіпами м'язових груп із прогрес-баром відсотка відновлення.
   - Підсвічування кольором: м'ятний (`IceCyanPrimary`) для готових до тренування, приглушений для тих, що відновлюються.
4. **Швидка дія:** Можливість натиснути на готову групу м'язів для швидкого запуску тренування з цією групою.
5. **Детальний діалог/шторка розкриття:** Перегляд аналітики по кожному м'язу (час останнього тренування, скільки годин минуло, рекомендований час наступної сесії).

## 3. Push-сповіщення при повному відновленні м'язів

1. **Канал сповіщень:**
   - Створення `apex_muscle_recovery_channel` («Відновлення м'язів») із пріоритетом `IMPORTANCE_DEFAULT`.
2. **Фонове планування сповіщень (`MuscleRecoveryNotificationReceiver` / `AlarmManager`):**
   - Після завершення тренування система визначає точний час відновлення кожної задіяної групи м'язів (`lastTrainedTimestamp + targetHours`).
   - Реєструє відкладене сповіщення через `AlarmManager` (або сповіщає при досягненні готовності).
   - Текст сповіщення: *«⚡ М'язи готові до навантаження! Грудні та Дельти повністю відновилися (відпочинок 48–60 год). Час для нового тренування!»*.
3. **Обробка дозволів (`POST_NOTIFICATIONS`):**
   - Дозвіл задекларовано в `AndroidManifest.xml`.
   - Запит дозволу в інтерфейсі, якщо він ще не наданий.
4. **Кнопка перевірки/тестування сповіщення:**
   - Можливість надіслати тестове сповіщення та увімкнути/вимкнути нагадування.

## 4. План змін у файлах

1. **`app/src/main/java/com/example/engine/MuscleRecoveryEngine.kt` (новий файл):**
   - Фізіологічні інтервали (48–72 год) для `MuscleGroup`.
   - Моделі `MuscleRecoveryStatus`, `MuscleRecoverySummary`.
   - Розрахунок відновлення за сесіями та підходами.
   - Генерація тексту рекомендації для тренування на сьогодні.

2. **`app/src/main/java/com/example/service/MuscleRecoveryNotificationHelper.kt` (новий файл):**
   - Створення каналу сповіщень `apex_muscle_recovery_channel`.
   - Планування сповіщень через `AlarmManager` та `PendingIntent`.
   - `MuscleRecoveryNotificationReceiver` для показу сповіщення, коли час настав.

3. **`app/src/main/java/com/example/ui/ApexViewModel.kt`:**
   - Реактивний потік `muscleRecoverySummary: StateFlow<MuscleRecoverySummary>` на основі `allCompletedSets`.
   - Планування оновлення сповіщень після завершення сесії.
   - Метод надсилання тестового пуш-сповіщення про готовність м'яза.

4. **`app/src/main/java/com/example/ui/screens/TrainingTab.kt`:**
   - Інформаційна картка «Готовність м'язів та рекомендація» на головному екрані тренувань.
   - Відображення списку м'язів, бейджів готовності та таймерів до наступного тренування.

5. **`app/src/main/AndroidManifest.xml`:**
   - Реєстрація `MuscleRecoveryNotificationReceiver`.

## 5. План верифікації
- Перевірка компіляції (`compile_applet`).
- Перевірка точних розрахунків годин та відновлення (48 год для малих груп, 72 год для великих).
- Перевірка коректності відображення інформаційної картки на головному екрані «Тренування».
